# Beads Map 0.2.10 — invited external beta

This is the first fixed Beads Map release intended for use beyond its original development workspace. It gives macOS developers already using Beads a local visual DAG, repository switching, graph exploration, and narrowly scoped metadata editing. The release is deliberately marked as a prerelease: the core workflow is usable and continuously tested, but broader platform support and workflow mutation remain outside the beta boundary.

## 1. Release status

- Version: `0.2.10`
- Git tag: `v0.2.10`
- Channel: invited external beta and GitHub prerelease
- Distribution: immutable GitHub release with attached wheel, source distribution, checksums, and a fixed-tag source fallback

## 2. Audience and prerequisites

This beta is for developers or maintainers who already use Beads and want to inspect one repository-scoped task graph at a time.

- macOS is supported; Linux remains best effort; Windows is unsupported.
- Python 3.11 or newer and `uv` are required.
- Beads `bd >=1.1,<2` must be installed and available on `PATH`.
- The selected repository must already contain an initialized `.beads/` directory.

## 3. Installation and start

Install the reviewed wheel attached to the immutable release:

```bash
uv tool install "https://github.com/heliopais/beads-map/releases/download/v0.2.10/beads_map-0.2.10-py3-none-any.whl"
beads-map --version
beads-map /path/to/your/repository
```

The reported application version must be `beads-map 0.2.10`.

If a source build is preferable, install from the same immutable tag:

```bash
uv tool install "git+https://github.com/heliopais/beads-map.git@v0.2.10"
```

## 4. Safety boundary

Beads Map serves only on loopback and validates the exact local Host and API Origin. State-changing requests also require a fresh random capability created at launch. Repository paths and view preferences remain in the user's local configuration; issue snapshots are not persisted by the app.

Graph reads use `bd --readonly export`. Explicit Save may change only title, description, priority, assignee, and labels through one allowlisted `bd update` command. Beads Map does not initialize, repair, migrate, synchronize, create, delete, claim, close, reopen, defer, or rewire Beads issues.

These controls protect against unrelated webpages and DNS-rebinding-style access. They do not protect against malicious software running as the same user, privileged browser extensions, browser compromise, or a modified local installation. See [security.md](../security.md) for the complete threat model.

## 5. Known limitations

- One repository and one current-state DAG are displayed at a time; there is no cross-repository graph or history playback.
- The supported rendering envelope is 1,000 displayed issues and 3,000 relationships. Larger scopes require filtering or an explicit best-effort override.
- The native folder picker is macOS-specific. Linux is not covered by the same hands-on product verification, and Windows is unsupported.
- Metadata editing is intentionally limited to five fields. Workflow-state changes, relationship editing, creation, deletion, and Beads synchronization stay in the CLI.
- The app is a foreground local process. There is no daemon, hosted service, automatic update check, or telemetry.

## 6. Upgrade and rollback

Upgrades are explicit. Review the newer release, then replace the version in its release-wheel URL and force reinstall. To roll back, reinstall an earlier release wheel the same way. Because this is the first tagged release, the immediate fallback is to reinstall `v0.2.10` or uninstall the tool:

```bash
uv tool install --force "https://github.com/heliopais/beads-map/releases/download/v0.2.10/beads_map-0.2.10-py3-none-any.whl"
uv tool uninstall beads-map
```

Neither action modifies Beads repositories. Uninstalling also leaves the local repository catalog in place.

## 7. Verification and reproducibility

The release is cut only after the Linux unit/build/wheel lane and the macOS browser/real-Beads lane pass for the tagged commit. The browser journey covers empty first run, real repository loading, status filtering, node selection, details, and relationship context against checksum-pinned Beads 1.2.2.

The GitHub release contains a wheel, source distribution, and `SHA256SUMS`. Download and verify the distributed files with:

```bash
gh release download v0.2.10 --repo heliopais/beads-map
shasum -a 256 --check SHA256SUMS
```

The tagged [ci.yml](../../.github/workflows/ci.yml) is the canonical reproduction recipe. It creates two independent builds from exact `git archive` extractions, hash-pins the build backend, fixes the build environment, normalizes source-archive metadata, and requires the wheel and source distribution to compare byte for byte. The successful tag workflow retains those checked files as its release candidate; the same files and checksum manifest are then attached to the immutable GitHub release.
